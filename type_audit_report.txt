## 二、统计汇总

### autoload 系统（30个文件）
- 公开函数缺返回值标注：81 个
  - 其中容器泛型缺失（Array → Array[T]）：16 个 ⚠️ 高优先级
  - 其中返回 Variant 需明确类型：1 个 (get_balance_param) ⚠️ 中优先级
  - 其中返回 void（副作用函数）：约 64 个 ℹ️ 可选标注

### Enemy.gd（1294行）
- 公开函数缺返回值标注：14 个（全部为 void 副作用函数）

### Town.gd（2015行）
- 公开函数缺返回值标注：0 个 ✓ 类型标注完整

## 三、优先级建议

### 🔴 立即补充（本周完成，影响 API 清晰度）

#### 1. ConfigLoader 的 10 个 get_all_* 函数 + 1 个 get_balance_param
- 补充 `-> Array[Dictionary]` 泛型标注
- 这些是配置驱动架构的核心 API，被所有系统调用
- 影响范围：EquipmentSystem/AffixWorkshop/SkillSystem 等
- **工作量：11 处修改，约 30 分钟**

#### 2. 其他系统的 6 个 Array 返回值
- AchievementSystem/BuildPresets/PartySystem/RosterSystem/SaveSystem/EndgameSystem
- **工作量：6 处修改，约 20 分钟**

**第一阶段总计：17 处修改，约 1 小时**

### 🟡 重构时补充（提升可维护性）

#### 1. Enemy.gd 的 14 个公开函数
- 待拆分文件时同步补充 `-> void` 标注
- 非紧急，但有助于重构时理解副作用边界

#### 2. autoload 中的 64 个 void 函数
- 可选补充 `-> void`（GDScript 允许省略）
- 优先级：事件注册类 > 状态修改类 > 反馈效果类

### 🟢 不必补充（推断已足够）

1. **变量声明** - `var x = 5` 已推断为 int，不必强制标注
2. **私有函数** - `func _internal()` 内部实现细节，按需标注
3. **简单赋值返回** - `return true/false/0/""` 类型明确

## 四、工程策略

### ❌ 不建议：全量标注
- 721 个函数 + 2399 个变量 = 成本巨大
- GDScript 有类型推断，强制标注收益递减

### ✅ 建议：增量标注策略

**第一阶段（本周）- 核心 API 类型明确化**
- 补充 ConfigLoader 的 11 个核心 API
- 补充其他系统 6 个 Array 函数
- **总工作量：17 处修改，1 小时**

**第二阶段（重构 Enemy.gd 时）- 副作用边界明确化**
- 同步补充 Enemy.gd 的 14 个函数标注
- 拆分职责时明确各模块的类型契约

**第三阶段（按需）- 按需渐进式补充**
- 遇到类型相关 bug 时，局部补充标注辅助排查
- 新增代码强制要求类型标注（可通过 CI 检查）

## 六、结论

**是否建议立即大规模补类型？**
❌ 否。建议**仅在重构时按需补充**，但有 17 个核心 API 需立即补充泛型标注。

**理由：**
1. GDScript 的类型推断已覆盖大部分场景
2. 强制标注 2399 个变量成本过高，收益递减
3. 但 **容器泛型标注**（Array[T]）对 API 清晰度影响巨大，必须补充
4. ConfigLoader 作为配置驱动架构的核心，其类型契约必须明确

**建议行动：**
1. 本周完成 17 个核心 API 的泛型标注（1 小时）
2. Enemy.gd 重构时同步补充类型标注
3. 新增代码要求类型标注（通过 code review 或 CI 检查）
