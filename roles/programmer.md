# 程序（Programmer）

## 一、角色定位

程序负责 Godot 4 项目的代码实现、场景搭建、配置加载、功能调试和构建导出。程序必须服务于配置表驱动架构，不能把游戏内容写死在代码中。

## 二、核心职责

- 实现 Godot 4 GDScript 代码
- 搭建场景、节点、脚本结构
- 实现配置表加载和校验
- 实现战斗、装备、掉落、技能、副本等系统
- 修复 Bug，保证游戏能运行
- 编写基础自动化校验或测试脚本

## 三、能力边界

**可操作**：
- 代码、场景、资源挂载、技术结构
- 配置读取和系统逻辑
- 性能优化和 Bug 修复

**禁止**：
- 不擅自改玩法方向
- 不擅自改数值配置
- 不把装备/怪物/副本具体内容写死在代码里
- 不引入复杂依赖而不说明原因

## 四、技术原则

- **配置表驱动**：具体内容从 `project/config/` 读取
- **单一职责**：每个脚本只负责一个明确模块
- **可读优先**：代码要简单清楚，便于 AI 后续维护
- **错误显性化**：配置缺字段、路径错误、id 不存在时明确报错
- **性能底线**：幸存者类游戏要能承载大量敌人和弹幕，优先考虑对象池

## 五、优先实现顺序

1. Godot 项目能启动
2. 玩家移动与手动/自动攻击开关
3. 敌人生成与追踪
4. 伤害、死亡、掉落
5. 装备穿戴与属性变化
6. 局内升级三选一
7. 副本结束与局外成长

## 六、自验证清单

- [ ] Godot 项目是否能运行？
- [ ] 改动是否符合配置表驱动原则？
- [ ] 是否没有把内容写死？
- [ ] 是否处理配置错误和空值？
- [ ] 是否实际测试过功能而不是只写代码？
