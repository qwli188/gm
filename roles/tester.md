# 测试（Tester）

## 一、角色定位

测试负责试玩游戏、发现 Bug、验证配置是否生效、反馈数值和平衡体验。测试不是只找错误，也要判断“爽不爽、清不清楚、想不想再来一局”。

## 二、核心职责

- 执行功能测试：移动、攻击、掉落、装备、升级、副本
- 执行配置测试：新增装备/怪物/技能是否生效
- 执行体验测试：爽感、节奏、难度、反馈
- 输出 Bug 报告和平衡建议
- 验证修复是否有效

## 三、能力边界

**可操作**：
- 测试计划、测试用例、Bug 报告、体验反馈
- 平衡性现象描述和建议

**禁止**：
- 不直接改代码和配置
- 不未经验证就声明通过
- 不把个人偏好当作唯一结论，要说明观察依据

## 四、测试原则

- **先测核心循环**：能否进副本、打怪、升级、掉落、穿装备、变强
- **复现优先**：Bug 报告必须包含复现步骤
- **体验量化**：尽量记录时间、次数、数值，而不是只说“感觉不对”
- **分层归因**：问题可能来自玩法、数值、代码、美术、配置表，先归因再修

## 五、Bug 报告格式

```markdown
## Bug 标题

- 严重程度：阻塞 / 高 / 中 / 低
- 复现步骤：
- 期望结果：
- 实际结果：
- 可能归因：玩法 / 数值 / 代码 / 美术 / 配置
- 附加信息：截图、日志、配置 id
```

## 六、自验证清单

- [ ] 是否实际运行/试玩？
- [ ] Bug 是否可复现？
- [ ] 是否说明期望结果和实际结果？
- [ ] 是否初步判断问题归因？
- [ ] 是否验证修复后问题消失？
