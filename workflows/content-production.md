# 内容制作流程（Content Production Workflow）

> 最常用的流程：制作人想加装备/怪物/副本/技能等具体内容时走这个流程。
> 本流程确保内容从设计→数值→实现→测试完整闭环,且符合配置表驱动原则。

---

## 一、流程适用场景

- 加新装备/词缀
- 加新技能
- 加新怪物/精英/Boss
- 加新副本/波次
- 扩展已有内容（如给装备加新词缀、给副本加新机制）

**不适用**：改玩法规则、改系统架构（走玩法设计流程）；调全局数值（走数值平衡流程）。

---

## 二、标准流程（6 步）

```
制作人提需求
   ↓
1. 需求澄清（内容设计师）
   ↓
2. 内容设计（内容设计师）→ 输出配置表草稿
   ↓
3. 数值评估（数值策划）→ 确认/调整数值
   ↓
4. 制作人审核 ← 决策点
   ↓
5. 代码实现（程序 + 美术）
   ↓
6. 测试验证（测试）→ 通过 or 回到步骤3
```

---

## 三、各步骤详解

### 步骤 1：需求澄清（内容设计师）

**输入**：制作人需求（如"我想加一把吸血剑"）

**内容设计师要做**：
- 确认类型：装备?技能?怪物?
- 确认定位：它是哪个流派的?稀有度?
- 确认参考：和哪个现有内容类似?
- 如果需求模糊,给制作人多个备选方向

**输出**：明确的设计目标

---

### 步骤 2：内容设计（内容设计师）

**内容设计师要做**：
1. 读取对应规范模板（如 `specs/equipment-config.tmpl.md`）
2. 读取现有配置表（如 `config/equipment.json`）
3. 参考现有内容,设计新内容的字段
4. 填写完整的 JSON 条目（含 design_note）
5. 确认 id 唯一、tags 支持流派、引用的其他 id 存在

**输出**：配置表 JSON 草稿（未填最终数值）

**示例**：
```json
{
  "id": "weapon_vampire_blade",
  "display_name": "吸血之刃",
  "slot": "weapon",
  "rarity": "rare",
  "tags": ["melee", "lifesteal", "physical"],
  "base_stats": { "damage": "待数值策划", "attack_speed": 1.2 },
  "fixed_affixes": ["affix_lifesteal"],
  "design_note": "吸血流核心武器,配合高攻速最强。"
}
```

---

### 步骤 3：数值评估（数值策划）

**数值策划要做**：
1. 读取 `config/balance.json` 和 `specs/numerical-formula.tmpl.md`
2. 评估新内容的数值是否平衡（对比同级/同稀有度内容）
3. 计算 DPS、强度、与现有构筑的协同
4. 填写最终数值或给出调整建议
5. 确认不破坏"多种流派可行"的原则

**输出**：数值评估报告 + 填好数值的 JSON

**示例报告**：
```
吸血之刃数值评估：
- 稀有度 rare,对标同级武器平均 DPS 约 15-18
- 建议 damage=22, attack_speed=1.5
- DPS = 33,略高于平均但合理（吸血效果需贴脸有风险）
- 与"高攻速流"协同强,不破坏平衡
- 通过
```

---

### 步骤 4：制作人审核 ← 关键决策点

**制作人要审**：
- 设计符合我的意图吗?
- 它能加入哪个流派?是我想要的吗?
- design_note 说的定位清楚吗?
- 数值看起来合理吗?（不需要懂计算,问数值策划"会不会破坏平衡"）

**制作人可以**：
- 通过 → 进入步骤5
- 要求调整 → 回到步骤2或3,说明哪里不符合预期
- 否决 → 停止流程

---

### 步骤 5：代码实现（程序 + 美术）

**程序要做**：
1. 读取配置表规范和现有代码
2. 确认新内容用的 kind/effect 是否已实现
3. 如果需要新逻辑,实现并标注
4. 将 JSON 条目追加到配置表文件
5. 运行游戏,确认内容能加载且不报错

**美术要做**：
1. 根据 design_note 和题材(西方奇幻暗黑)查找免费素材
2. 确认授权可商用,记录到 CREDITS.md
3. 将资源路径填入配置表
4. 确认资源在游戏里能正确显示

**输出**：可运行的游戏版本,新内容已生效

---

### 步骤 6：测试验证（测试）

**测试要做**：
1. 运行游戏,进入副本
2. 确认新内容出现（装备掉落、怪物生成等）
3. 确认效果生效（吸血回血、词缀触发等）
4. 确认数值正确（伤害、血量等与配置一致）
5. 试玩体验,反馈爽感/平衡性
6. 发现问题填 Bug 报告或平衡建议

**输出**：测试报告

**如果不通过**：
- 代码 Bug → 程序修复 → 重测
- 数值不平衡 → 回到步骤3,数值策划调整
- 体验不好 → 制作人决定是调整还是重做

**如果通过**：流程结束,内容正式加入游戏

## 四、派发 prompt 模板

制作人助理派发时用这个模板：

```
【内容设计师】
你收到制作人需求："{需求原文}"

启动加载（按顺序读取）：
1. constitution.md
2. roles/content-designer.md
3. specs/GUIDE.md
4. specs/{对应规范模板}.tmpl.md
5. project/config/{对应配置表}.json
6. project/GDD.md

任务：
- 澄清需求（如有模糊,列出备选方向）
- 设计内容,输出配置表 JSON 草稿
- 标注"待数值策划"的字段

交付：JSON 草稿 + design_note
```

## 五、常见问题

**Q：能不能跳过数值策划直接实现？**
A：小改动（如改个显示名、加个标签）可以,但涉及数值（伤害、血量、掉落率）必须经数值策划评估。

**Q：美术素材还没找到能不能先实现功能？**
A：可以。先用占位路径,程序实现逻辑,后续美术补上。

**Q：测试不通过要全部推倒重来吗？**
A：看问题类型。代码 Bug 修 Bug；数值不平衡调数值；玩法方向错了才需要重做。

---

## 六、成功标准

一个内容制作任务的成功标准：
- [ ] 配置表 JSON 格式正确,id 唯一
- [ ] 数值策划确认平衡性
- [ ] 制作人确认符合意图
- [ ] 程序确认能加载运行
- [ ] 美术素材授权合规
- [ ] 测试确认功能和数值正确
- [ ] 体验符合"爽感、成就感"目标
